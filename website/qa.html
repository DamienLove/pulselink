QA / Beta Testing

End‑to‑end checks for Safety, Beacon, and Deep Links

Home Safety Beacon Deep Links Store iOS QA / Beta

Use two Android devices if possible: one running Safety, another with Beacon (or Safety as well). Ensure notifications and location are allowed.

Report bugs with context, device model, and logs/screenshots at: damiennichols.com/report-bug.

0) Install & Permissions

  1. Install latest APKs from Releases.
  2. Grant Notifications, Microphone (Safety), Location (Safety), Contacts (optional), and DND override (Beacon).
  3. Verify app can run in background (disable battery optimizations if prompted).

1) Trusted Contacts, Links, Approvals

  1. Add a trusted contact on Device A; accept link/approval on Device B if prompted.
  2. Verify contact appears under Trusted Contacts on both devices after sync.
  3. Remove and re‑add to test idempotency and rule enforcement.

2) Messaging and Signals (FCM over Wi‑Fi)

  1. Ensure both devices are on Wi‑Fi (SIM optional). Disable mobile data if you want to force Wi‑Fi‑only.
  2. Send a standard message from A → B; verify receipt and notification.
  3. Send an urgent message from A → B; verify louder tone/priority channel.
  4. Background B and repeat; confirm delivery within 5–10 seconds via Firebase Cloud Messaging (FCM).

3) Emergency Flow (Safety)

  1. Trigger Safety on A (voice phrase or deep link). Observe alert sheet and countdown if applicable.
  2. Verify B receives alert with a Google Maps link. Open map shows approximate location.
  3. Test Cancel: use cancel phrase or in‑app cancel (enter PIN if enabled). Verify B receives cancellation.

4) Beacon DND Bypass

  1. On B, enable DND. Mark A’s identity as Favorite in Beacon.
  2. Send an urgent/keyword message from A → B. Verify audible alert in DND, correct siren tone.
  3. Disable Favorite and retry; confirm no DND bypass occurs.

5) Deep Links

Test the links on device B (with app installed):

  • pulselink://assistant/emergency → starts emergency flow.
  • pulselink://assistant/cancel → cancels if active.
  • pulselink://assistant/checkin → sends check‑in.
  • pulselink://assistant/message?contact=Test&text=Hello → composes/sends message.
  • See Deep Links for full list.

6) Home Screen Widget

  1. Add the PulseLink widget: long‑press home screen → Widgets → PulseLink.
  2. Tap Emergency, Cancel, and Check‑in; verify each action performs as expected and logs an entry in Diagnostics.

7) WebRTC Signaling (beta, if available)

  1. If a WebRTC (beta) toggle exists in Settings on both devices, enable it.
  2. Initiate a session from A (e.g., from a linked contact details). Observe that B receives offer/answer and the session connects.
  3. Background B; verify the session recovers or gracefully falls back to relay. Disable beta when finished.

8) Background & Edge Cases

  • Lock screen delivery: alerts still notify within 10 seconds.
  • Airplane mode then Wi‑Fi only: flows still work over Wi‑Fi.
  • Reboot device: app resumes listeners on unlock; deep links still open.
  • Permissions revoked: app shows clear prompts and degrades gracefully.

Pass/Fail, Diagnostics & Reporting

  • Mark each step pass/fail with device model and OS version.
  • Attach screenshots or screen recordings for failures.
  • Export logs from Settings → Diagnostics → Export logs and attach to your report.
  • Submit via bug report form. Include steps, expected vs. actual, logs if available.
